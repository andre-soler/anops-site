Algum desses soa familiar?

São os problemas que mais encontro em sistemas de pequenas empresas e em projetos entregues por freelancers.

  • O sistema caiu e você soube pelo clienteSem monitoramento, a queda só aparece quando alguém reclama.
  • Cada atualização é um riscoDeploy feito à mão, por FTP ou copiando arquivos, sem volta fácil se der errado.
  • O backup nunca foi testadoTer backup não garante nada. A pergunta é se ele volta quando você precisa.
  • Só uma pessoa sabe como o servidor funcionaNada documentado, nada versionado. Se ela sumir, o conhecimento vai junto.

Ansible Server Setup

Uma VM Ubuntu vazia vira um servidor protegido e monitorado com um comando.

AnsibleTerraformAzureGitHub Actions
Problema
Configurar servidor à mão é lento, cada máquina fica diferente da outra e um erro de digitação pode trancar o acesso.
Solução
Terraform cria a VM na Azure com acesso SSH liberado só para o IP do administrador. Ansible aplica quatro roles: sistema base, segurança (SSH, UFW, Fail2ban), Docker e a stack de monitoramento. Os mesmos roles rodam num laboratório local e na Azure.
Resultado
Execução idempotente (a segunda rodada termina sem mudanças), configuração de SSH e sudo validada antes de aplicar, segredos no Ansible Vault e CI obrigatório na main.

Um problema do caminhoVMs retomadas da suspensão voltavam com o relógio horas atrasado, e o apt recusava as listas de pacotes. A correção foi forçar a sincronização do relógio antes de qualquer tarefa de pacote.

Linux Monitoring Stack

Observabilidade completa de um servidor Linux, instalada com um script.

PrometheusGrafanaLokiAlloyBash
Problema
Sem monitoramento, disco cheio, falta de memória e serviço travado só aparecem quando o sistema já caiu.
Solução
Métricas com Prometheus, logs do systemd com Alloy e Loki, dashboard único no Grafana e um relatório diário de saúde enviado por e-mail. Dashboards e alertas são provisionados por arquivo, então um Grafana novo sobe idêntico.
Resultado
Cinco regras de alerta por e-mail, cada uma testada provocando o problema de propósito, com filtros de ruído para evitar alerta falso.

Um problema do caminhoA fórmula comum de uso de disco mostrava cerca de 7% enquanto o df mostrava 2%. A diferença eram os 5% de blocos que o ext4 reserva para o root. Dashboard e alerta passaram a usar a mesma conta do df.

Central FastCoffee

Sistema de gestão de uma operação de máquinas de café, com clientes, contratos e cobrança.

DockerNginxGitHub ActionsLinux VPS
Problema
Um sistema com dados de clientes e integração de pagamento precisava ir para a internet com segurança e atualizações sem risco.
Solução
Aplicação em Docker numa VPS Linux, Nginx com HTTPS para os subdomínios do app e da API, SSH protegido, firewall UFW, Fail2ban e usuário do banco com permissões mínimas.
Resultado
Deploy automático via GitHub Actions a cada push na main, merge só com pull request e CI verde, monitoramento de disponibilidade e alertas de dependências vulneráveis.
